# 第 14 期｜训练与推理大不同！为什么聊天时大模型的 Embedding 词表早已“彻底冻结”？

## 💡 本节核心要点

- **严格区分大模型的“两段人生”**：**训练（Training）**是出厂前耗资数百万美元、用反向传播与 SwiGLU 反复雕琢参数的“寒窗苦读期”；日常聊天则是**推理（Inference）**，模型只做单向前向计算，处于不改一比特权重的“考场答题期”。
- **密码学铁证破除“边聊边改词表”迷思**：对 DeepSeek 1.3B 全部 **219 个权重张量（1,346,471,936 个参数）** 进行推理前后 SHA-1 密码学哈希校验，发生改变的张量数为 **`0`**——聊天时词表、注意力与 FFN 权重连 1 个比特都不会变。
- **静态死词表 + 动态活语境**：推理时第 0 层 `[32256, 2048]` 词表是彻底锁死的只读字典，“苹果（`id=17144`）”在任何句子里的初始向量永远 100% 相同（余弦相似度恒为 `1.0000`）。
- **语境分化靠的是 24 层动态激活**：模型能分辨“买一台苹果”与“咬一口苹果”，靠的是第 1～24 层多头注意力与 FFN 将不同前文实时注入当前词向量，在高层空间实现自动分群。

## 一、 破除初学者头号迷思：训练与推理，完全是两套运行状态

看完第 12～13 期的反向传播与梯度进化大戏，很多同学立刻会追问：**“那我平时在网页上跟 DeepSeek 或 ChatGPT 聊天时，每发一句话，它是不是也在后台偷偷算梯度、实时修改词向量表和 FFN 权重？”**

答案干脆利落，三个字：**绝不会！**

把大模型想成一名高考生：**训练（Training）**是考前十二年狂刷真题、对答案、改写脑回路的过程；而模型上线供我们聊天则是**推理（Inference）**，相当于走进了高考考场——**考生只能调动早已定型的脑回路单向写答案，绝不可能一边考试一边翻标准答案改写大脑结构！**

一张表从六个维度把两套运行状态彻底划清界限：

| 对比维度 | 训练过程（Training 寒窗苦读期） | 推理过程（Inference 考场答题期） |
| :--- | :--- | :--- |
| **1. 数据流动方向** | **双向往返**：前向传播算概率 + 反向传播传梯度 | **单向直通**：仅从第 0 层到第 24 层单向前向传播 |
| **2. 是否计算导数梯度** | **是**：必须沿链式法则求偏导，算 13.46 亿参数梯度 $\nabla$ | **否**：完全关闭求导引擎（开启 `torch.no_grad()`） |
| **3. 词表与权重是否改变** | **持续动态改写**：每一步都在微调词表、注意力与 FFN | **100% 彻底冻结（Frozen）**：所有权重只读不写，纹丝不动 |
| **4. 算力与显存开销** | **极高**：需存激活值、梯度与优化器状态，千卡集群数周 | **极低**：仅加载只读权重，普通个人笔记本毫秒级响应 |
| **5. 核心数学目标** | **雕琢函数 $F$ 本身**：最小化误差 $\text{Loss} = -\ln P$ | **调用固定函数 $Y=F(X)$**：输入上文 $X$，抽样下一个词 $Y$ |
| **6. 时间尺度与阶段** | 模型上线前，由 AI 实验室耗时数周一次性或分阶段完成 | 模型上线后，用户每次敲回车键的几十毫秒内实时触发 |

## 二、 密码学铁证：13.46 亿参数推理前后 SHA-1 指纹分毫不差

光说不练假把式，我们直接上密码学 **SHA-1 哈希算法**，给 DeepSeek 1.3B 全部 **219 个权重张量（`1,346,471,936` 个参数）** 拍了数字指纹。哪怕十几亿个浮点数里只有 1 个二进制比特在聊天时偷偷变了脸，SHA-1 指纹都会瞬间面目全非。

推理前拍完指纹，接着给模型喂入“我在苹果公司吃了一个苹果”及多组测试句跑完 24 层生成，再抽查指纹比对：

| 权重张量名称（Tensor Name） | 张量形状 | 推理前 SHA-1 指纹（FP32 / BF16） | 推理后 SHA-1 指纹（FP32 / BF16） | 校验结果 |
| :--- | :---: | :---: | :---: | :---: |
| **`model.embed_tokens.weight`** | `[32256, 2048]` | `31be160760f8`（`aca97c6467b7`） | `31be160760f8`（`aca97c6467b7`） | **100% 相同** |
| **`layers.0.self_attn.q_proj.weight`** | `[2048, 2048]` | `c6f7bf5625e0`（`5d6291418469`） | `c6f7bf5625e0`（`5d6291418469`） | **100% 相同** |
| **`layers.12.mlp.up_proj.weight`** | `[5504, 2048]` | `18a1aa7d95fd`（`ce65fce94d44`） | `18a1aa7d95fd`（`ce65fce94d44`） | **100% 相同** |
| **`layers.23.self_attn.o_proj.weight`** | `[2048, 2048]` | `c98b2802d06b` | `c98b2802d06b` | **100% 相同** |
| **`lm_head.weight`** | `[32256, 2048]` | `2ac8b3cb3994`（`a2df31529069`） | `2ac8b3cb3994`（`a2df31529069`） | **100% 相同** |
| **全模型 219 个权重张量总计** | **13.46 亿参数** | **219 个张量初始指纹** | **`before == after` 逐位比对** | **改动数：`0`** |

实测结果铁板钉钉：**`changed_tensors = 0`（改动张量数为 0）**！具体到第 0 层静态词表里编号 **`17144`** 的“苹果”，它的模长永远死锁在 **`8.0703`**，前 6 维坐标雷打不动地焊死在 `[0.0398, -0.2314, 0.1011, 0.2002, -0.1553, 0.0908]`——哪怕你跟它促膝长谈一万句，这串数字也纹丝不动。

## 三、 静态死词表如何算活语境？4 个“苹果”的 24 层动态分群实测

词表彻底焊死了，每次查“苹果（`id=17144`）”吐出来的初始向量一模一样，那模型聊起天来靠什么见人说人话、分辨手机和水果？

我们做了一组**四句控制变量实验**——把同一个词元 **“苹果（`id=17144`）”** 全放在句尾，只换前文修饰词，追踪这 4 个“苹果”从第 0 层到第 23～24 层的余弦分群与续写分流：

![冻结词表下的动态语境分化：4个“苹果”在第24层的聚类实测](../assets/fig4_context_clusters.png)

| 实验句子与标签 | 句尾 ID | 第 0 层两两余弦 | 第 8 层余弦 | 第 23～24 层同簇余弦 | 第 23～24 层跨簇余弦 | 句尾 Top-2 预测词与概率 |
| :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **$S_1$ 数码·一台**：“我买了一台全新的**苹果**” | `17144` | **`1.0000`** | 与 $S_2$: `0.8371` | **数码簇 (`S1 ↔ S2`)**：<br>第 24 层 **`0.8404`**（`0.7792`） | **`S1 ↔ S3`**：<br>第 23 层 **`0.4492`** | **① `电脑` (`33.88%`)**<br>② `手机` (`23.28%`) |
| **$S_2$ 数码·公司**：“他入职了著名的**苹果**” | `17144` | **`1.0000`** | 与 $S_3$: `0.6864` | 同上（紧聚为科技品牌簇） | **`S2 ↔ S3`**：<br>第 23 层 **`0.4334`** | **① `公司` (`75.22%`)**<br>② `电脑` (`2.07%`) |
| **$S_3$ 水果·一口**：“我咬了一口脆甜的**苹果**” | `17144` | **`1.0000`** | 与 $S_4$: `0.9273` | **水果簇 (`S3 ↔ S4`)**：<br>第 24 层 **`0.8886`**（`0.9375`）<br>第 23 层 **`0.8818`** | **`S3 ↔ S2`**：<br>第 23 层 **`0.4334`** | **① `，` (`56.82%`)**<br>② `。` (`12.88%`) / `汁` (`1.40%`) |
| **$S_4$ 水果·一颗**：“我洗了一颗新鲜的**苹果**” | `17144` | **`1.0000`** | 与 $S_2$: `0.7406` | 同上（紧聚为生鲜水果簇） | **`S4 ↔ S2`**：<br>第 23 层 **`0.5057`** | **① `，` (`47.72%`)**<br>② `。` (`23.26%`) / `树` (`1.49%`) |

妙极了！第 0 层 4 个“苹果”余弦全是 **`1.0000`**；可穿过 24 层注意力与 SwiGLU 知识库后，两个数码句紧紧抱团（余弦 **`0.8404`**），两个水果句聚成另一簇（余弦高达 **`0.8886`**），跨簇相似度则跌至 **`0.4334`**！最终数码句后精准接出 **`“电脑 / 手机 / 公司”`**，水果句后稳稳接出 **`“，”`**！

> **🧠 底层思想提炼：“静态参数存通识”与“动态激活算语境”的二元协奏**
> 推理时把权重焊死，是为了防止用户的随机提问污染模型耗费万亿语料练出的知识江山。大模型用**彻底冻结的静态权重（Static Weights）**守住通识骨架，再用**随句子流转的 24 层动态激活张量（Dynamic Activations）**实时碰撞出千变万化的语境火花！

## 📜 科学史故事栏：从“一词一坐标”的死胡同，到动态表征摩天大楼

2013～2014 年，当 **Word2Vec** 和 **GloVe** 横扫 NLP 界时，静态词向量曾风光无限。可大家很快撞上了一词多义的南墙：因为没有高层动态网络，`"apple"` 在宇宙里永远只配拥有一个固定坐标，被迫尴尬地卡在“水果簇”和“科技公司簇”正中间的无人区里。

2018 年，艾伦研究所的 **ELMo** 与 OpenAI 的初代 **GPT** 联手破局：**推理时干脆把底层静态词表彻底冻结，只当成每个词的“出厂起跑线”；在词表头顶加盖一座 24 层高的动态注意力与 FFN 摩天大楼！** 从此，词表依然只读不动，但每个词爬完这栋大楼后，都拥有了随上下文实时呼吸的鲜活生命。
